# Prompt optimization experiment

User selected current-pipeline optimization and a before/after measurement.

- [x] Freeze baseline prompt, existing labels and input hashes. Use all 11 existing comparison cases, preserving partial labels and humanReviewed=false.
- [x] Test metric aggregation (failures, unknown usage, thinking tokens, latency quantiles).
- [x] Implement a compact candidate preserving instructions, full transcripts, dynamic checklist rules and repair feedback.
- [x] Compare both variants through the existing Gemini adapter and evaluation service, in an isolated SQLite database, alternating order, two repetitions per case. Same model/low thinking/8192 output/120s timeout. Reserve up to 4 attempts per evaluation; stop on provider failures. Cap 176 calls; no unbounded retries.
- [x] Report agreement, full-dialogue agreement, errors, input/output/thinking tokens, estimated standard-rate cost and p50/p95 evaluation latency. Include all attempts and failures; unknown usage stays unknown. Price is a tariff estimate, not an invoice.
- [x] Promote candidate only if measured agreement and gross errors do not regress and cost/median latency improve; otherwise retain baseline and report findings.
- [x] Run suite, typechecks, build and independent code review.

Existing examples have been used in earlier tuning. This is paired calibration, not independent accuracy. Runtime inputs/outputs remain ignored; publish aggregate report only. No changes to working database, env or remote deployment.

Outcome: 44 evaluations, 49 calls. Baseline retained: compact RU labels regress 40/42 -> 38/42, repair count 0 -> 3, p95 3719 -> 5614ms. Both variants had one rate-limit call with unknown usage. Report uses known-usage standard-tariff estimates; raw totals remain unknown. Independent reviewer findings fixed (frozen baseline, cost inference, partial-label naming, incomplete CLI status).
