# CQA: состояние реализации на 7 ноября 2026

Изменения реализованы локально в `codex/cqa-backend`, без публикации. Базовый режим — прежний v4 с Gemini. Новый режим оценки включается явно: `AI_EVALUATION_POLICY=facts-first-v1`. Автоматического перехода на GPT или новый промпт нет.

## Что работает

- Короткий самостоятельный промпт: факты и доказательства, отдельные `resolved`/`unresolved`, строгая проверка структуры и ссылок на реплики. Неизвестное не превращается в N/A: для N/A нужны правило неприменимости, проверенный фрагмент и причина. Отрицательные ответы требуют проверенного диапазона; положительные — подтверждающих реплик.
- Общий предел нового режима: четыре фактических вызова, один повтор временной ошибки, одно исправление и явно настроенный независимый проверяющий в пределах общего времени. Противоречия, неопределённость и грубые нарушения направляются человеку; предварительный результат не публикуется как итоговый балл.
- Ручная проверка и апелляции используют журнал решений, ревизии и идемпотентность. Исходный ответ модели сохраняется; человеческий итог показан отдельно.
- Диагностика учитывает попытки, токены, известные тарифы и повторное использование кэша. Неизвестная стоимость обозначается как неизвестная. Сравнение прогонов допускается для одинакового текста диалога.
- Обзор, очередь проверки, операции, причины потери баллов и переходы к доказательствам. Светлая/тёмная тема и крупный текст.
- Сохранение чек-листа отделено от активации. Ошибка загрузки профилей не выбирает незаметно последний черновик; доступен повтор загрузки. Старые оценки имеют предупреждение о версии.
- Примеры для будущих оценок требуют отдельного одобрения человеком. По умолчанию выключены; при включении — максимум два совпадающих по критерию, языку и каналу примера с исключением текущего текста и зарегистрированных контрольных данных.
- Добавлены миграции SQLite с резервной копией существующей базы перед изменениями.

## GPT и измерения

Адаптер OpenAI, режим `reasoning_effort=none`, проверка схемы и инструмент парного сравнения готовы. Ключ обнаружен, но два минимальных синтетических обращения вернули HTTP 429 / `insufficient_quota`. Повторять этот отказ автоматически нельзя; он классифицируется как `BILLING_REQUIRED`.

Кандидат сравнения — `gpt-6-luna`. Качество GPT, его задержка и фактическая стоимость в этом проекте **не измерены**. Вывод о превосходстве над Gemini отсутствует. Официальная карточка: https://developers.openai.com/api/docs/models/gpt-6-luna.

Финальный промпт нового режима проверен одним синтетическим запросом Gemini: результат `resolved`, 681 входной и 172 выходных токена, 2241 мс. Это только проверка совместимости. Один пример не доказывает точность, экономию или ускорение; сравнивать его время с запросом другого состава некорректно.

После восстановления квоты сначала выполняется маленькая проверка:

```sh
node --env-file=.env --import tsx qa/gemini/openai-smoke.ts
```

Затем парный прогон на одинаковых замороженных данных:

```sh
node --env-file=.env --import tsx qa/gemini/provider-ab.ts \
  --reference runtime/prompt-na-v6/frozen-reference.json \
  --database runtime/prompt-na-v6/source.sqlite --repeats 2 --run
```

Без `--run` инструмент только готовит план, не вызывает модели. Этот A/B сравнивает провайдеров на v4, чтобы не смешивать смену модели со сменой промпта. Новый режим требует отдельного эксперимента. Имеющаяся разметка не подтверждена независимыми экспертами; совпадение с ней нельзя представлять как независимую оценку точности. Отчёт учитывает все запланированные исходы, ошибки, p50/p95 и неизвестные расходы. Максимум для 12 диалогов и двух повторений — 192 вызова, а не гарантированный денежный лимит.

## Проверка и границы

- `npm test -- --maxWorkers=2`: 36 файлов, 414 тестов прошли. При одновременном запуске неограниченного числа тестов, проверки типов и сборки два теста превысили 5 секунд; ограниченный прогон прошёл без увеличения тайм-аутов. Проверка дедлайна переведена на управляемые часы.
- Проверки типов приложения и QA, форматирования, production-сборки и smoke-прогон выполнены. Smoke использует временную базу и не вызывает модели.
- Проверка в браузере: ручное разрешение неопределённого ответа с доказательствами, итог в обзоре, активация версии, предупреждение об устаревшей оценке, переход к реплике, темы. Проверены фактические ширины 360, 768 и 1107 CSS px без горизонтального переполнения. 1440 px не подтверждены: среда ограничила доступную ширину.
- Ревью кода обнаружило автоматический выбор неактивной версии при сбое загрузки профилей; исправление прошло отдельное ревью и регрессионные тесты.

Это локальная реализация рабочего процесса, а не подтверждение всей продуктовой концепции или готовности к production. Авторизация и роли ещё не реализованы: используется демонстрационный проверяющий. Жёсткое резервирование денежного бюджета не реализовано; `AI_HARD_BUDGET_USD` отклоняется конфигурацией. Семантические проверки покрывают ограниченный набор правил, а определение семейств переводов по идентификаторам — эвристика. Контрольные хеши нужно зарегистрировать до использования примеров. Автоматическая генерация критериев и расширенный аудит остаются вне этой поставки.
