# Качество ИИ и стоимость моделей

Проверено 7 ноября 2026 года. Для CQA важны решения по восьми критериям, порядок действий, N/A, доказательства и отдельный флаг грубых нарушений на RU/KZ/EN. Общий рейтинг LLM не доказывает качество на этих диалогах.

**Точность выше 95% пока не достигнута и не подтверждена.** Имеющаяся разметка подготовлена ассистентом, частично использовалась для настройки и не является независимым Ground Truth. Проверки кода не измеряют смысловую точность.

В командном setup `main` после `f54204ca` указаны `AI_PROVIDER=none` и `GEMINI_MODEL=gemini-3.5-flash`. Это конфигурация шаблона команды. Ниже фактически замерены **Flash-Lite 3.5**, Flash-Lite 3.1 и Flash 3.8; результаты Lite не относятся автоматически к Flash 3.5. Командный выбор модели и личный `.env` эта работа не подменяет.

## Что исправлено

- Генерация использует текущие критерии, их шкалы, разрешение N/A и реальные ID реплик. Для стандартных правил операторские доказательства ограничены репликами оператора; для идентификации разрешена также система. Клиентские и бот-реплики остаются в проверенных участках контекста. Пользовательские критерии сохраняют собственную семантику.
- Общие примеры в prompt не навязывают старые баллы изменённой пользователем шкале. Порядок уточнений и уже выполненной передачи на проверку рассматривается отдельно от обещания передать вопрос.
- Сервер независимо проверяет полноту ответов, роли, русский язык объяснений, N/A и доказательства, затем сам считает баллы. Схема и инструкции не доказывают смысловую достаточность цитаты.
- Добавлены явные адаптеры Groq, локального Ollama, OpenAI и DeepSeek. Перехода на другую модель или платный API при сбое нет. Ошибки, лимиты, обрыв генерации и расход токенов сохраняются отдельно.
- В benchmark есть метрики по критериям и языкам, доля полностью совпавших диалогов, покрытие и интервал Уилсона по диалогам. Проверка цели >95% требует фактический чек-лист, замороженные настройки, полную разметку, независимые диалоги и человеческую проверку. Неполный запуск или высокий процент на двух примерах не проходит эту проверку.

Основные оставшиеся расхождения: `needs` true вместо N/A, качество ведения диалога, приветствие и завершение. Исправление структуры ответа не устраняет эти смысловые ошибки. Нулевое число ошибок gross на нескольких примерах также не доказывает высокую полноту обнаружения нарушений.

## Как подключить бесплатную альтернативу

Groq требует собственный ключ и именно бесплатный аккаунт. Поддержка строгого JSON заявлена для [GPT-OSS 20B/120B и Qwen 3.8 27B](https://console.groq.com/docs/structured-outputs); доступные лимиты смотрите в [документации и консоли аккаунта](https://console.groq.com/docs/rate-limits). Ключ хранится только в локальном `.env`:

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=your_local_key
GROQ_MODEL=openai/gpt-oss-120b
AI_REASONING_EFFORT=low
AI_MAX_OUTPUT_TOKENS=8192
```

После установки Ollama и локальной модели можно выбрать:

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
OLLAMA_MODEL=qwen3.5:4b
```

Адаптер Ollama принимает только loopback HTTP и отклоняет cloud-суффиксы; [OpenAI-совместимый API Ollama](https://docs.ollama.com/api/openai-compatibility) не требует облачного ключа. Локальные модели и многогигабайтные загрузки автоматически не устанавливались.

Ни код приложения, ни API-ключ сами по себе не подтверждают платёжный тариф облачного аккаунта и не устанавливают денежный предел у провайдера. До будущего облачного запуска нужно проверить Free plan/отключённый биллинг в консоли. Платные альтернативы остаются выключенными без явной конфигурации.

## Что нужно для обоснованной цели >95%

Нужны независимые экспертные ответы по всем восьми критериям, отдельные группы шаблонов и представительная тестовая выборка RU/KZ/EN, включая грубые нарушения и N/A. До этого можно честно говорить о совпадении с локальными ожиданиями и технической надёжности.

Текущий quality gate намеренно строже одного среднего процента: требует >95% совпадений в каждом языке, отсутствие ошибок gross и нижнюю границу 95% интервала для полностью правильных независимых диалогов выше 95%. Это инженерный критерий допуска, который нельзя заменить самооценкой confidence модели. Для примера, даже 10/10 полностью правильных независимых диалогов дают нижнюю границу лишь около 72%; этот пример не является оценкой текущей модели.

Рекомендуемый следующий шаг: добавить бесплатный Groq-ключ, сравнить GPT-OSS 120B на том же замороженном наборе без подстройки ожидаемых ответов и получить человеческий разбор спорных решений. При текущем запрете на платные вызовы платные модели не следует использовать даже в качестве второго оценщика.
