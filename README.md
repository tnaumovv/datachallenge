# Paradox · Freedom CQA

**AI-платформа для оценки диалогов и улучшения клиентского сервиса от команды Paradox.**

Freedom CQA превращает чаты и транскрипты звонков в понятную картину качества: от общего среднего балла до конкретной реплики, которая повлияла на оценку. Команда получает единое рабочее пространство для анализа, проверки спорных ответов и настройки стандартов обслуживания.

[![CQA checks](https://github.com/tnaumovv/datachallenge/actions/workflows/ci.yml/badge.svg)](https://github.com/tnaumovv/datachallenge/actions)

## Что умеет проект

- **Обзор качества.** Средние баллы, покрытие оценками, основные причины потерь и интерактивный график накопительного среднего по завершённым оценкам.
- **Чаты и звонки в одном месте.** Импорт, поиск, фильтры по группе, языку и каналу, пакетная оценка до 100 диалогов.
- **Объяснимые результаты.** Баллы по критериям, обоснования и переход прямо к цитате в исходном диалоге.
- **Гибкие чек-листы.** Веса, шкалы, правила N/A, отдельные флаги нарушений и сохранение новых версий.
- **Проверка человеком.** Очередь спорных оценок, решения проверяющего и работа с апелляциями с сохранением исходного результата.
- **История и диагностика.** Сохранённые прогоны, сравнение результатов, попытки вызовов и данные о расходах, когда они доступны.
- **Три темы оформления.** Светлая, тёмная и чёрная темы, сохранение выбора, крупный текст и анимации с поддержкой уменьшения движения.
- **Многоязычные диалоги.** Работа с RU, KZ и EN.
- **Оценка по проверяемым признакам.** Анализатор `cqa-evaluator-v7.2` применяет N/A до начисления баллов, проверяет приветствие первой реплики оператора и выводит оценки по сохранённым шкалам.
- **Точные цитаты действий.** Уточнения и завершение подтверждаются дословными фрагментами; итог или предложение помощи проверяются отдельно от прощания.
- **Регламенты и рекомендации.** Поиск по базе знаний, ссылки на использованные источники и рекомендации оператору по результатам оценки.
- **Обновлённый интерфейс.** Адаптивная навигация, единые выпадающие списки, встроенный плеер записей и выбор активного чек-листа в обзоре.

В DEV-наборе команды **Paradox** подготовлены результаты для **65 диалогов: 60 чатов и 5 звонков**. Экспорт доступен в [results/dev/results.json](results/dev/results.json), описание набора и конфигурации — в [статусе подготовки](docs/SUBMISSION.md).

Контрольный **FBroker** также обработан: **10 чатов, 10 успешных результатов, 0 ошибок** — [results/prod/results.json](results/prod/results.json). Дополнительный **SWAP** сохранён локально: 3 чата, оценка ещё не запускалась.

## Быстрый запуск

Потребуются **Node.js 24** и npm. Версия Node зафиксирована в [.nvmrc](.nvmrc). SQLite работает внутри приложения, отдельный сервер базы данных устанавливать не требуется.

```sh
git clone https://github.com/tnaumovv/datachallenge.git
cd datachallenge
npm ci
```

Если используете nvm, перед установкой зависимостей выполните `nvm use`.

Создайте файл настроек, если его ещё нет:

```sh
[ -f .env ] || cp .env.example .env
```

Соберите и запустите приложение:

```sh
npm run build
npm start
```

Откройте **[http://127.0.0.1:3000/overview](http://127.0.0.1:3000/overview)**. Интерфейс и API обслуживаются одним процессом. Проверка доступности сервера: [http://127.0.0.1:3000/api/health](http://127.0.0.1:3000/api/health).

### Данные и AI-оценка

При первом запуске приложение создаёт локальную базу `runtime/cqa.sqlite`. В разделе **«Диалоги» → «Импортировать»** можно загрузить JSON или подключённый источник организаторов.

Для импорта из источника организаторов укажите полную выданную ссылку в `ORGANIZER_API_URL` в `.env`, затем выберите нужную группу, например `DEV`. Рабочая база и исходные транскрипты хранятся локально: 65 реальных диалогов появятся после импорта или подключения вашей существующей базы. Файл результатов в репозитории содержит экспорт оценок.

Для новых AI-оценок выберите провайдера и задайте ключ. Пример настройки Gemini в `.env`:

```dotenv
AI_PROVIDER=gemini
GEMINI_API_KEY=your_api_key
GEMINI_MODEL=gemini-3.5-flash-lite
GEMINI_THINKING_LEVEL=low
AI_MAX_OUTPUT_TOKENS=8192
AI_REQUEST_TIMEOUT_MS=120000
```

После изменения `.env` перезапустите сервер. Выберите доступную вашему аккаунту модель; доступ и квота определяются провайдером. Поддерживаются также Groq, OpenAI, DeepSeek и локальный Ollama — примеры настроек находятся в [.env.example](.env.example), варианты подключения — в [руководстве по моделям](docs/AI_MODELS.md).

По умолчанию в шаблоне задан `AI_PROVIDER=none`: можно импортировать данные, работать с чек-листами и читать сохранённые результаты. Внешние AI-вызовы включаются после настройки провайдера.

### Посмотреть интерфейс без настройки API

```sh
npm run demo:web
```

Откройте адрес из терминала — обычно [http://127.0.0.1:5174](http://127.0.0.1:5174). Это отдельный деморежим с вымышленным диалогом и готовыми ответами, удобный для знакомства с интерфейсом. Основная рабочая база в этом режиме не используется.

## Режим разработки

Запустите API и интерфейс в двух терминалах:

```sh
# Терминал 1 — API
npm run dev
```

```sh
# Терминал 2 — Vite
npm run dev:web
```

Откройте адрес Vite из терминала. Запросы `/api` направляются на `http://127.0.0.1:3000`. Для другого адреса API задайте `CQA_API_URL`. На одном API-порту запускайте один сервер: `dev` или `start`.

Сворачиваемое меню, Tailwind и пути компонентов описаны в [инструкции по интеграции sidebar](web/SIDEBAR.md).

## Как устроена работа

1. **Импортируйте диалоги.** Загрузите группу и отфильтруйте нужные чаты или звонки.
2. **Выберите чек-лист.** Используйте активную версию или создайте новую под свои критерии.
3. **Запустите оценку.** Приложение обработает выбранные диалоги и сохранит результаты.
4. **Изучите обзор.** Посмотрите средние баллы, покрытие и критерии с наибольшими потерями.
5. **Откройте доказательства.** Перейдите от критерия к точной реплике в транскрипте.
6. **Разберите спорные случаи.** Подтвердите или измените ответ через проверку и апелляции.

AI оценивает критерии и указывает доказательства, а итоговый балл вычисляет сервер по правилам чек-листа. Исходные ответы сохраняются вместе с историей последующих решений.

## Разделы приложения

| Страница       | Назначение                                        |
| -------------- | ------------------------------------------------- |
| `/overview`    | Средние баллы, график, покрытие и причины потерь  |
| `/dialogs`     | Импорт, поиск, фильтрация и пакетная оценка       |
| `/dialogs/:id` | Транскрипт, результаты, цитаты и история прогонов |
| `/review`      | Очередь проверки и решения по спорным оценкам     |
| `/checklists`  | Версии чек-листов и активные профили              |
| `/appeals`     | Обращения и пересмотр критериев                   |
| `/knowledge`   | Регламенты, версии документов и проверка поиска |
| `/operations`  | История вызовов и диагностика                     |

## Технологии

**Frontend:** React, TypeScript, Vite, Recharts, CSS с общими токенами трёх тем.

**Backend:** Node.js, Express, Zod, SQLite и адаптеры AI-провайдеров.

**Проверки:** Vitest, Testing Library, Supertest и GitHub Actions.

```text
web/src/           Страницы, компоненты, темы и API-клиент
server/src/        API, импорт, оценка, хранение и аналитика
shared/            Общие контракты и тестовые примеры
qa/gemini/         Инструменты проверки моделей и результатов
results/           Экспорт результатов
scripts/           Smoke-проверка и служебные команды
docs/              Документация проекта
```

## Проверка проекта

```sh
npm test
npm run typecheck
npx tsc -p qa/gemini/tsconfig.json
npm run format:check
npm run build
npm run smoke
```

GitHub Actions запускает эти проверки после пуша. Smoke-проверка использует отдельную временную базу и проверяет собранное приложение, импорт, расчёты и сохранение данных после перезапуска без обращения к внешней AI-модели.
