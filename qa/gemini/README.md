# Проверка Gemini на RU / KZ / EN

Небольшой воспроизводимый набор для проверки действующего backend через HTTP API. Он проверяет сохранённые ответы, расчёт баллов, точность цитат и повторный запрос без нового вызова модели. Файлы приложения в `server/` и `shared/` не изменяются.

`cases.json` содержит ручные ожидания для девяти синтетических DEV-чатов: по три на язык. Это **не Ground Truth организаторов и не оценка точности на всём наборе**. Для неоднозначных случаев проверяются только явно указанные критерии. Исходные транскрипты в Git не хранятся. RU-001 и последующая проверка KZ-015 использованы для уточнения инструкций; похожие KZ-001 и EN-001 — языковые проверки, а не независимый контрольный набор.

`checklist.json` сохраняет восемь исходных критериев, веса, шкалы, разделы и правила N/A. Меняются только пояснения к инструкциям. В частности, общая навигация не засчитывается как проведённая идентификация, одного прощания недостаточно для полного завершения, а отсутствие грубого нарушения тоже требует проверенного участка.

## Подготовка отдельной копии

Работайте в отдельном worktree с Node.js 24 и установленными зависимостями (`npm ci`). В его локальном `.env` укажите:

```dotenv
PORT=3011
HOST=127.0.0.1
DATABASE_PATH=runtime/gemini-qa.sqlite
AI_PROVIDER=gemini
GEMINI_API_KEY=ваш_локальный_ключ
GEMINI_MODEL=gemini-3.6-flash
AI_MAX_OUTPUT_TOKENS=8192
ORGANIZER_API_URL=
```

Запустите `npm run dev`. Порт 3011 и отдельная база отделяют проверку от демонстрационного сервера на 3000. Не копируйте рабочую БД поверх тестовой и не добавляйте `.env` в Git. Исторический профиль ниже использовал стандартный уровень рассуждений провайдера. Теперь backend также поддерживает необязательный `GEMINI_THINKING_LEVEL` (`minimal`, `low`, `medium`, `high`) для совместимых моделей; настройка входит в ключ кэша. Пустое значение сохраняет стандартный режим.

Сохраните DEV-экспорт локально, например в `runtime/dev-export.json`. Поддерживаются массив записей организаторов, их JSON-конверт, либо ответ `GET /api/conversations?groupId=DEV`. Скрипт выбирает только девять перечисленных синтетических чатов и отвергает записи с аудио:

```sh
node --import tsx qa/gemini/prepare.ts runtime/dev-export.json
```

Подготовка импортирует выбранные записи и сохраняет отдельную версию чек-листа. Повторная подготовка использует существующую идентичную версию. Она не вызывает Gemini. Скрипт отказывается работать с удалённым хостом или демонстрационным портом 3000.

## Живые проверки

Начните с трёх языковых примеров:

```sh
node --import tsx qa/gemini/run.ts --run p1-ru-001 p1-kz-001 p1-en-001
```

После просмотра результатов можно запустить шесть дополнительных случаев:

```sh
node --import tsx qa/gemini/run.ts --run --max-calls 9 p1-ru-003 p1-ru-014 p1-kz-013 p1-kz-015 p1-en-006 p1-en-013
```

`--run` явно включает реальные запросы. Скрипт отправляет диалоги последовательно и останавливается при `failed`. Одна оценка может вызвать до четырёх обращений к модели по правилам backend; запуск всего DEV не производится. `force` не используется. После завершённой оценки скрипт повторяет тот же запрос и проверяет возврат прежнего ID и неизменность результата.

По умолчанию бюджет — шесть новых вызовов. Перед каждой новой задачей резервируются четыре попытки; при недостаточном остатке запуск останавливается, даже если отдельные оценки раньше укладывались в один вызов. Это лимит данного запуска, а не оставшаяся квота Google: другие приложения и предыдущие тесты тоже расходуют квоту. Число можно явно задать через `--max-calls`.

Для чтения уже сохранённых оценок без POST и без генерации используйте нулевой бюджет. В этом режиме повторный POST для проверки кэша также не выполняется (`cacheVerified=null`):

```sh
node --import tsx qa/gemini/run.ts --run --max-calls 0 p1-kz-015 p1-ru-003 p1-en-006
```

Фильтр модели при таком чтении — `gemini-3.6-flash`; его можно изменить через `--model`. Если оценки для выбранной версии чек-листа нет, скрипт завершится с указанием непройденных случаев, не создавая новую задачу.

Для другого тестового порта задайте `CQA_API_URL`. Отчёты и полные ответы сохраняются только в игнорируемой папке `runtime/gemini-qa/`. `usage` относится к сохранённой оценке: при повторном чтении кэша это исторические токены, а не новый расход. Неизвестные счётчики остаются `null`.

Проверяйте не только совпадение значений: прочитайте объяснения и цитаты. Без справочника продукта нельзя независимо подтвердить фактические правила тарифов или регистрации. Не переносите результаты этих примеров на реальные звонки, дикцию, интонацию или скрытый контрольный набор.

## Проверки без внешних вызовов

```sh
npm test -- qa/gemini/review.test.ts
npx tsc -p qa/gemini/tsconfig.json
```

Тесты проверяют, что инструмент различает техническую валидность и смысловые ошибки, замечает подменённую цитату, неверный итог и отсутствие нужного доказательства. Они не вызывают Gemini.

## Результаты 7 ноября 2026

Подробные ID оценок, попытки, счётчики и замечания — в [отчёте](reports/2026-11-07.json).

Выбран явный `gemini-3.6-flash`. С исходными уточнениями успешно обработаны девять разных чатов. После обнаруженной смысловой ошибки уточнены консультация и завершение, затем повторно проверены три случая: KZ-015, RU-003 и EN-006. Остальные шесть на последней версии не перезапускались ради сохранения квоты.

| Базовая языковая проверка |  Итог | Вызовы успешной оценки |
| ------------------------- | ----: | ---------------------: |
| RU-001                    | 92,31 |                      1 |
| KZ-001                    | 92,31 |                      1 |
| EN-001                    | 92,31 |                      1 |

Всего в изолированной базе: 13 задач, 12 завершённых оценок, 19 вызовов модели с учётом ошибок и повторов. Известный расход — 76 870 токенов; для семи неуспешных попыток usage отсутствует, поэтому полный расход неизвестен. Ранее выполненные пробные вызовы вне этой базы в эти цифры не входят. Все 13 записей пережили перезапуск обычного собранного backend без изменений; повторные чтения не вызывали модель.

Обнаружены HTTP 503 из-за нагрузки и один 429 с указанием бесплатного суточного лимита 20 запросов для модели. Новые вызовы прекращены. Перед обработкой контрольных данных нужно проверить доступную квоту; отчёт не гарантирует её остаток. Скрипт теперь ограничивает собственный бюджет и поддерживает чтение без генерации.

Последний KZ-015 верно учёл передачу вопроса на проверку, но объяснения получились на украинском вместо русского. Этот дефект языка остаётся открытым. Некоторые остальные значения в нём также изменились, поэтому рост итогового балла нельзя целиком приписывать исправлению двух критериев. Профиль годится для проверяемых небольших запусков и демонстрации сохранённых результатов; готовность к автоматической массовой оценке не заявляется.

Справочная документация: [уровни рассуждений Gemini](https://ai.google.dev/gemini-api/docs/generate-content/thinking?hl=en), [структурированные ответы](https://ai.google.dev/gemini-api/docs/structured-output?lang=rest).

## Новая проверка после исправлений

Текущий default-чек-лист уточняет порядок сбора деталей, выполненную и обещанную передачу на проверку и завершение диалога. EN-006 теперь имеет `needs=false`, итог 85 согласно сохранённому решению пользователя; старый JSON-отчёт фиксирует прежние результаты и не переписывается. Новая версия prompt не использует кэш прежней версии.

Валидатор отклоняет положительные стандартные оценки без реплик оператора (системная идентификация допустима), отсутствие проверенного участка при false/0/NA, неполное покрытие реплик при стандартном gross=false и явное несоответствие языка объяснения. Специальные ограничения ролей распознают исходные v1 и текущие default-формулировки. Изменённые инструкции, включая замену встроенного ID или старые дополнительные QA-формулировки, проходят общие проверки без навязанного операторского источника: критерий может оценивать клиента. Языковая проверка допускает исходные цитаты и имена. Она не доказывает русский язык во всех случаях; проверка ролей также не доказывает смысловую достаточность цитаты.

Для новых примеров сначала сохраняется локальный frozen-reference с хешами транскриптов и чек-листа, моделью, prompt/configuration ID и ожидаемыми ответами. Не передавайте разметку модели. `benchmark-run.ts` отправляет только ID диалога и чек-листа и использует `originalAnswers`/`originalScore`. Файл разметки и полные результаты остаются в игнорируемом `runtime/ai-quality/`.

```sh
npm run qa:benchmark -- --run --reference runtime/ai-quality/frozen-reference.json --max-calls 16
# Сверить уже сохранённые результаты без POST и новых вызовов модели:
npm run qa:benchmark -- --run --reference runtime/ai-quality/frozen-reference.json --max-calls 0
```

Runner принимает только локальный HTTP API (по умолчанию порт 3000; другой задаётся через `--api`). Реальный запуск сохраняет выбранные оценки в приложении; до него сделайте резервную копию БД. Резервируются до четырёх вызовов на следующую оценку, после технического сбоя запуск останавливается. Метрики показывают завершённые, неуспешные и незапущенные случаи, совпадение критериев, ошибки NA/gross и среднюю абсолютную ошибку балла. Регрессии отделены от новых примеров. Разметка ассистента и небольшие синтетические примеры не являются независимой точностью по человеческому Ground Truth.
